# Changes of 2026-11-05 (final polish before the demo video)

Backend measured on this date: `tsc --noEmit` clean, **141 suites / 1351 Jest tests pass**. Flutter was **not** compiled in
this pass (no SDK in the working environment): run `flutter analyze` and `flutter test` on your machine before building.

## Fixed (found by running the full suite on the merged tree: 9 suites / 17 tests were red)
- Spending scopes: a scope is usable when it has at least one limit of its own (daily, per purchase or category).
  It was wrongly required to have a daily limit. A scope with no limit at all is still refused (fail closed).
- `POST /api/policy/preview` returns `appliedScopeId` and `scope`; `POST /api/orders/create` returns `appliedScopeId`.
- Rule-based Barista fallback now enforces the selected scope (it ignored it before).
- Barista no longer blocks while Profile has unsaved edits: it uses the saved profile and says so.
- `GET /api/orders/:id/evidence` was registered twice, so the merchant variant was unreachable. It is one route now:
  the owning shopper (session) or the merchant with a valid `X-Ops-Key` (required even when `DASHBOARD_PUBLIC=true`).
- The defense text in the evidence package is a fixed template; its item kind is now `generated-statement`
  (was `ai-narrative`).
- Four web tests were updated to the new `#order-detail` page.

## Look
- iOS system palette from `design/tokens.json` for web and Flutter (grouped background, systemBlue, system
  green/orange/red, true-black dark mode). `theme.css`, dashboard, merchant, split and verify pages follow the tokens.
