# AI Café — PayPal Commerce Agent API SDK

[![Built with APIMatic][apimatic-badge]][apimatic-url] [![License: MIT][license-badge]][license-url] [![Python 3.10+][python-badge]][python-url]

The AI Café — PayPal Commerce Agent API SDK for Python provides access to the AI Café — PayPal Commerce Agent API REST APIs from Python applications.

> [!TIP]
> **Looking for a specific signature, model, enum, or error type?** This SDK ships a generated
> **[SDK map](sdk-map.md)** -- a lookup index of the SDK's entire Python surface. Consult it before
> scanning the source tree; details under [SDK map](#sdk-map).

Agentic-commerce API for the PayPal AI Hackathon. A natural-language AI agent prepares a shopping cart, but the **server owns all prices** and a **human authorizes every PayPal payment** — the agent never touches money. A read-only PayPal Ops Copilot lets a merchant audit activity. This spec powers SDK generation (APIMatic) and the Postman collection.

## Installation

Add the Python SDK to your project from its folder, with whichever package manager your project uses. Give each tool a path containing a slash, such as `../ai-caf-pay-pal-commerce-agent-api` — a bare folder name is looked up on PyPI instead, and resolves to whatever project holds that name there:

```bash
pip install <path-to-sdk>
```

```bash
uv add <path-to-sdk>
```

```bash
poetry add <path-to-sdk>
```

## Quick Start

### Synchronous client

Construct `AiCafPayPalCommerceAgentApiClient` with keyword arguments, and call `close()` when you are done. Every argument is optional; the full list is in the [SDK map](sdk-map.md).

```python
from ai_caf_pay_pal_commerce_agent_api import AiCafPayPalCommerceAgentApiClient

client = AiCafPayPalCommerceAgentApiClient(
    session_id="YOUR_API_KEY", bearer_auth="YOUR_BEARER_TOKEN", ops_key="YOUR_API_KEY", environment="production"
)

# TODO: call endpoints here -- see api-reference.md

client.close()
```

Alternatively, scope it -- `with AiCafPayPalCommerceAgentApiClient(...) as client:` closes the pool on exit; see [Best Practices](#best-practices).

`Client` is exported as an alias of `AiCafPayPalCommerceAgentApiClient`, so `from ai_caf_pay_pal_commerce_agent_api import Client` also works.

The SDK accepts every model-typed input in two interchangeable spellings, both type-checked: the typed model, or a plain dict with the same keys -- the `OrDict` and `Model | ModelDict` unions in the [SDK map](sdk-map.md). Pick whichever suits the call site: the dict form needs no import, while the model form adds a keyword-checked constructor and editor completion.

### Asynchronous client

`AsyncAiCafPayPalCommerceAgentApiClient` mirrors `AiCafPayPalCommerceAgentApiClient` with **identical method names**, and every endpoint method is a coroutine. It takes the same arguments, with some differences -- for example, the transport argument is `custom_async_http_client`.

```python
from asyncio import run

from ai_caf_pay_pal_commerce_agent_api import AsyncAiCafPayPalCommerceAgentApiClient


async def main() -> None:
    client = AsyncAiCafPayPalCommerceAgentApiClient(
        session_id="YOUR_API_KEY", bearer_auth="YOUR_BEARER_TOKEN", ops_key="YOUR_API_KEY", environment="production"
    )
    # TODO: call endpoints here, awaiting each -- see api-reference.md
    await client.aclose()


run(main())
```

Alternatively, scope it -- `async with AsyncAiCafPayPalCommerceAgentApiClient(...) as client:` closes the pool on exit. Only the async spelling is `aclose`, matching httpx2; see [Best Practices](#best-practices).

`AsyncClient` is the exported alias. Each client accepts **only** its own transport argument; passing the other's is a `TypeError` at runtime and an error under mypy.

## Logging

The SDK logs every HTTP exchange through Python's standard `logging` module, under the `ai_caf_pay_pal_commerce_agent_api` logger, and configures nothing itself: with no logging set up, nothing is printed unless `AI_CAF_PAY_PAL_COMMERCE_AGENT_API_LOG` is set. Turn it on as for any library:

```python
import logging

logging.basicConfig()  # your application's handler; the root stays at WARNING
logging.getLogger("ai_caf_pay_pal_commerce_agent_api").setLevel(logging.INFO)  # the SDK's lines; DEBUG adds the dumps that logging_options turns on
```

Or set one environment variable before the process starts, for a run you cannot edit: `AI_CAF_PAY_PAL_COMMERCE_AGENT_API_LOG=info` writes the request and response lines, `AI_CAF_PAY_PAL_COMMERCE_AGENT_API_LOG=debug` adds the request headers, the request body and the response headers. If your application has configured logging, its handlers and format are used; otherwise the SDK writes to stderr.

Choose the detail with `logging_options`, a `LoggingOptions` from `ai_caf_pay_pal_commerce_agent_api.core`:

```python
from ai_caf_pay_pal_commerce_agent_api import AiCafPayPalCommerceAgentApiClient
from ai_caf_pay_pal_commerce_agent_api.core import LoggingOptions

client = AiCafPayPalCommerceAgentApiClient(
    logging_options=LoggingOptions(log_request_headers=True, log_response_headers=True, log_request_body=True)
)
```

A plain dict with the same keys is accepted too, as for every model-typed argument (see [Quick Start](#quick-start)): `logging_options={"log_request_headers": True}`.

| Option | Default | Effect |
| --- | --- | --- |
| `log_request_headers` | `False` | Log the sent headers at DEBUG, masked. |
| `log_response_headers` | `False` | Log the received headers at DEBUG, masked. |
| `log_request_body` | `False` | Log the request body at DEBUG: its text when in memory, a description when streamed. |
| `body_size_limit` | `32768` | Bytes of a logged body kept before it is cut. |
| `redaction_placeholder` | `"REDACTED"` | What a hidden value prints as. |
| `unmask_headers` | none | Header names to show although they are not on the safe list. |
| `mask_headers` | none | Header names to hide although they are on the safe list. |
| `mask_keys` | 11 credential names | Query and form keys whose values are always hidden; naming a set replaces the default. |

A single call can be quietened with `request_options={"log_level": logging.WARNING}`: records below that level are not written for that call. It never turns on a record the client's options leave off. Header, query and form values print `REDACTED` unless known safe; a JSON body is printed as sent, so enable `log_request_body` only where its content may be logged; a response body is never logged. The levels and every field are under **Logging** in the SDK map.

## Best Practices

> [!TIP]
> Use a **single `AiCafPayPalCommerceAgentApiClient` instance** for the lifetime of your application and reuse it across
> all requests. Each instance owns its own connection pool, so an instance per request forfeits
> connection reuse and leaks pools that are never closed.

Match the disposal to the client's lifetime: an application-lifetime client is closed once at shutdown with `close()` / `aclose()`; where the lifetime fits a block, `with AiCafPayPalCommerceAgentApiClient() as client:` / `async with AsyncAiCafPayPalCommerceAgentApiClient() as client:` releases it automatically. Both are idempotent, but a closed client is not reusable: the next call raises. The client closes **whatever transport it holds**, including one you supplied via `custom_http_client` / `custom_async_http_client`; if you intend to reuse your own transport across clients, don't hand its lifetime to a `with` block.

**Retries are on by default**: a failed idempotent request — a retryable status or no response at all — is sent again up to three times before the call gives up. Pass `retry_options=0` to turn it off, for instance in a test that stubs an error response; the policy and its defaults are under **Retries** in the SDK map.
